# Сайт-визитка Никиты

Статический сайт (HTML/CSS/JS, без фреймворков и сборки). Исходники — в
корне репозитория, проверочные инструменты — только в `devDependencies`.

- `index.html` — вся разметка и весь текст (редактируемый текст специально
  не вынесен в JS, см. раздел 6 ТЗ).
- `css/styles.css` — все стили (переменные палитры — в начале файла, `:root`).
- `js/*.js` — ES-модули: кнопка Telegram, свет за курсором, пауза анимаций на
  скрытой вкладке.
- `scripts/*.js` — служебные Node-скрипты (генерация favicon/og-image,
  поиск плейсхолдеров, проверки адаптива и веса страницы). На сам сайт не
  попадают.
- `qa/` — автопроверка (`run-qa.js`) и её результаты (скриншоты,
  JSON-отчёты — не в git, см. `.gitignore`, воспроизводятся командой).

## Как поменять тексты

Весь видимый текст лежит прямо в `index.html` — ищите нужный раздел по
`<h2>`/`id` секции (`projects`, `services`, `process`, `about`, `contacts`)
и правьте разметку напрямую, пересборка не нужна.

Места, которые нужно заполнить своими данными, помечены
`[ЗАПОЛНИТЬ: описание]`. Полный список с номерами строк:

```
npm run placeholders
```

На момент последнего прогона не заполнены: цены и сроки 4 услуг, сроки
этапов «как работаю», число правок после запуска, фото в «Обо мне» и
`canonical`/`og:url` (нужен домен — см. ниже). Заполнили — уберите
`[ЗАПОЛНИТЬ: ...]` и текст до/вместо него, `npm run placeholders` должен
перестать находить эту строку.

## Как добавить/обновить скриншоты проектов

Карточки в разделе «Проекты» (`#projects`) показывают реальные скриншоты
живых сайтов проектов (`assets/img/projects/*.webp`), а не макеты — скрипт
снимает их через Playwright и сжимает в WebP:

```
node scripts/capture-project-screenshots.js
```

Список проектов (URL и имя файла) — в начале этого скрипта, массив
`PROJECTS`. Чтобы добавить новый проект:

1. Добавьте в `PROJECTS` объект `{ slug, url }`.
2. Прогоните скрипт — получите `assets/img/projects/<slug>.webp`.
3. Скопируйте один из существующих `<article class="project-card">` в
   `index.html`, поправьте текст, ссылку и `src`/`alt` картинки.

**Не подделывайте скриншоты** — только реальные снимки настоящих проектов
(правило раздела 10 ТЗ). Если проекта ещё нет в сети, честнее оставить
место пустым с пометкой `[ЗАПОЛНИТЬ: ...]`, чем вставить чужой или
нарисованный макет.

## Как проверить сайт перед публикацией

```
npm install              # один раз
npm run qa                # html-validate, Playwright (3 вьюпорта), axe-core, Lighthouse mobile
npm run check:responsive  # 79 ширин 360–1920px без горизонтальной прокрутки
npm run check:weight      # вес HTML+CSS+JS без картинок, лимит 300 КБ
npm run placeholders      # список незаполненных мест
```

`npm run qa` поднимает локальный сервер на `http://127.0.0.1:4173` сам,
руками ничего запускать не нужно. Использует системный Chrome (или Edge как
фолбэк) через Playwright — отдельный браузер Playwright не ставится (см.
`DECISIONS.md`).

## Как выложить на GitHub Pages

1. Создайте репозиторий на GitHub и отправьте туда код (`git push`, если ещё
   не делали):
   ```
   git remote add origin <URL вашего репозитория>
   git push -u origin master
   ```
2. В репозитории на GitHub: **Settings → Pages → Source** → выберите ветку
   `master` и папку `/ (root)` → **Save**.
3. Через 1–2 минуты сайт будет доступен по адресу вида
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.
4. После публикации узнаете домен — впишите его в `index.html` вместо
   комментария `[ЗАПОЛНИТЬ: canonical и og:url/twitter:url ...]`: добавьте
   `<link rel="canonical" href="...">` и замените относительные
   `og:url`/`twitter:url` на абсолютные (раздел 6 ТЗ это явно допускает,
   когда домен уже известен).
5. Прогоните `npm run qa` ещё раз на опубликованном адресе (подставив его в
   `qa/run-qa.js` вместо локального, временно) — Lighthouse на реальном
   хостинге может отличаться от локального прогона.

Никаких шагов сборки нет — что в репозитории, то и видно на сайте.
