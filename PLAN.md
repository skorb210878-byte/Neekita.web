## Этап 6. Доводка: движение, reduced-motion, производительность, адаптив

- [x] Все анимации только `transform`/`opacity`, пауза при скрытой вкладке

- [x] Адаптив 360–1920 px без горизонтальной прокрутки, тач-цели ≥ 44 px.
- [x] Вес страницы без картинок ≤ 300 КБ. Изображений (WebP/AVIF, `loading="lazy"`)
      на странице пока нет — см. примечание ниже.

**Критерий:** Playwright-тест на 360×640..1920×1080 → `document.documentElement.scrollWidth
<= document.documentElement.clientWidth` на каждой ширине; реальный размер
HTML+CSS+JS без изображений (`Get-Item`/`du`-эквивалент в Node-скрипте) ≤ 300 КБ —
число приводится в отчёте. **Выполнено**:
- Анимации (`drift-one`/`drift-two` туман, `log-line-in` журнал работы) уже с
  этапа 2 используют только `transform`/`opacity`, отключаются в
  `prefers-reduced-motion` и ставятся на паузу через `.is-hidden`
  (`js/visibility.js`, `visibilitychange`) — проверено повторно, без изменений.
- Найден и исправлен реальный недостаток: `.project-card__link` («Открыть
  сайт →») не имел явной высоты, замерен Playwright на 390×844 — `44px`
  строки с `padding-top: 0.5rem` давали фактическую область клика ~29px.
  Исправлено на `display: inline-flex; align-items: center; min-height: 44px`
  (`css/styles.css`). Остальные интерактивные элементы (кнопки Telegram/MAX,
  skip-link) замерены тем же способом на 390×844: 50–56px — уже
  соответствовали требованию.
- `node scripts/check-responsive.js` — новый скрипт, прогоняет 79 ширин с
  шагом 20px от 360 до 1920 (включая 1920). Реальный вывод: все 79 — `OK`,
  `scrollWidth === clientWidth` на каждой, 0 провалов.
- `node scripts/check-page-weight.js` — новый скрипт, честно считает байты
  `index.html` + `css/styles.css` + `js/*.js` на диске. Реальный вывод:
  `index.html` 14587 + `styles.css` 14747 + 4 JS-файла (975+362+540+423) =
  **31634 байта (30.9 КБ)** — далеко в пределах лимита 300 КБ.
- **Про изображения:** на странице сейчас нет ни одного `<img>` — карточки
  проектов используют CSS-заглушку вместо скриншотов (решение этапа 3,
