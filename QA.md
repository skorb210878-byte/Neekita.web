### Проверка производительности («нет лагов на слабом устройстве»)

Не предполагается, не измерено на глаз — посчитано:
- **Активных таймеров одновременно: максимум 1.** Печать — рекурсивная
  цепочка `setTimeout` (`schedule()` в `js/heroCode.js`): каждый тик либо
  вызывает следующий шаг, либо (если `document.hidden`) сам себя
  перепланирует через 200мс — новый таймер создаётся только после того,
  как предыдущий уже сработал и завершился. Параллельных/накапливающихся
  таймеров нет, подтверждено логикой кода, а не угадыванием.
- **DOM-операций за «кадр» печати: 1.** На каждый символ — либо
  `textContent +=` в уже существующий `<span>` (тот же токен), либо
  создание одного нового `<span>` (смена токена/новая строка) через
  `insertBefore`. Полной пересборки окна нет никогда, кроме как при
  смене фрагмента (раз в ~30-40с, один `innerHTML = ''`).
- **Скролл:** `transform: translateY()` на одном общем контейнере строк
  (не на каждой строке отдельно), то есть одна композитная перерисовка
  на всё окно сразу — дешевле, чем анимировать 15+ строк по отдельности.
- Браузерная консоль чистая на всех 3 снимках обоих кругов (включая
  момент скролла и смены фрагмента) — проверено `page.on('console')` /
  `page.on('pageerror')` в тестовом прогоне, не только штатным
  `npm run qa` (который тоже 0 ошибок).
