# ТЗ: сайт-визитка веб-разработчика Никиты («пасмурно, все заняты делом»)

> **Как использовать:** положи файл в пустую папку проекта как `SPEC.md`, открой в ней Claude Code и отправь по очереди три сообщения из чата (вопросы → ответы и правила → `/goal`).

---

## 1. Цель

Визитка для владельцев малого бизнеса. За 30 секунд посетитель должен понять: кто я, что делаю, видны ли реальные работы, сколько это примерно стоит и как написать. Мрачная эстетика это оболочка: она не должна мешать читать и писать мне. Главное действие на сайте: **«Написать в Telegram»**.

## 2. Правила работы

1. Сначала изучи папку и ТЗ. Задай ВСЕ вопросы одним списком (не больше 10, к каждому вариант по умолчанию, см. раздел 3). После моих ответов больше вопросов не задавай: неясное решай по умолчанию, записывай в `DECISIONS.md` (что выбрал и почему) и продолжай.
2. Составь `PLAN.md`: этапы из раздела 8, у каждого проверяемый критерий (команда → ожидаемый результат). Дальше работай без остановок.
3. Ничего не объявляй готовым без доказательства: в отчёте приводи реальный вывод команд, а не пересказ. Если инструмент не запускается (например, Lighthouse), так и напиши в `QA.md`, результат не выдумывай.
4. После каждого этапа: проверки, `git commit`, отметка в `PLAN.md`. `git push` не делай.
5. Если одна и та же проверка не проходит 3 раза подряд, остановись и опиши проблему.
6. Версии пакетов закрепи. Комментарии в коде на русском.
7. Я работаю на Windows. Скрипты пиши на Node.js (не на bash), пути и команды должны работать в PowerShell.

## 3. Вопросы в начале (с вариантами по умолчанию)

3. Фото: моё собственное (обработаешь в тёмном стиле) или монограмма «Н» без фото? По умолчанию монограмма.
4. Какие проекты показывать, под каким статусом (концепт / реальный / в разработке) и можно ли называть клиентов? По умолчанию список из раздела 5, клиентов не называть.
5. Услуги, сроки и цены «от»? По умолчанию поля `[ЗАПОЛНИТЬ]`, ничего не придумывать.
6. Показывать ли возраст и город? По умолчанию возраст нет, город Екатеринбург да.
7. Предлагать ли «первый макет бесплатно»? По умолчанию нет.
8. Акцент: тусклый янтарь или глухой красный? По умолчанию янтарь.
9. Где публикуем: GitHub Pages (по умолчанию) или свой домен?
10. Ссылки на живые демо проектов, если есть.

## 4. Визуальный язык

Референс по настроению: фильмы «Социальная сеть» и «Бэтмен» (2022). Тёмные интерьеры, приглушённые цвета, низкий ключ света, никто не позирует, все заняты работой. Это настроение, а не материал для копирования.

**Нельзя:** кадры из фильмов, фото актёров, логотипы Facebook/Meta/DC/Batman и знак летучей мыши, цитаты и реплики из сценария, названия и имена персонажей, музыку. Всё на странице либо оригинальное, либо моё.

- **Палитра** (CSS-переменные в `:root`): фон `#0b0c0d`, поверхности `#121416` и `#181b1e`, линии `rgba(255,255,255,.08)`, текст `#d9dbdc`, второстепенный `#9aa0a4`, акцент ОДИН: янтарь `#d4893a` (или красный `#b3262b`, но красный только для декора, контраст текста на фоне у него ниже нормы). Всё остальное бесцветное. **Контраст текста не ниже 4.5:1**, даже на тёмном.
- **Шрифты** (Google Fonts, кириллица, `display=swap`): заголовки Barlow Condensed 600/700 (заглавные, плотный трекинг), текст Inter, метки и «код» JetBrains Mono.
- **Фактура:** зерно 3–5% (SVG `feTurbulence`), виньетка, два медленно дрейфующих размытых «туманных» слоя (только `transform`/`opacity`).
- **Свет:** на десктопе мягкое пятно света следует за курсором (радиальный градиент). Отключено на touch-экранах и при `prefers-reduced-motion`.
- **«Журнал работы» в hero:** моноширинные строки в стиле истории коммитов появляются по одной (декор, `aria-hidden`). Только реальные названия моих проектов. При reduced-motion показывается статично.
- **Композиция:** сетка 12 колонок, асимметрия, крупная типографика, номера секций «01 / Проекты» моноширинным шрифтом. Анимации сдержанные: появление при скролле, без отскоков.
- **Фото** (если есть): grayscale + контраст, при наведении тёплый оттенок.
- **Избегай шаблонного вида:** никаких фиолетовых градиентов, эмодзи, стоковых иконок, «стеклянных» карточек.

## 5. Контент и структура

Одностраничный сайт, секции по порядку. Тексты на русском, от первого лица, короткие, без пафоса (фразы «команда профессионалов», «индивидуальный подход» не писать). **Никаких выдуманных цифр, отзывов, клиентов и опыта.** Всё, чего не знаешь, помечай `[ЗАПОЛНИТЬ: что именно]`.

Известные факты: меня зовут Никита, делаю сайты, Telegram-ботов и Telegram Mini App; стек: HTML/CSS/JS, Three.js, Python (aiogram).

1. **Hero:** h1 вроде «Никита. Сайты, боты, Mini App.» (можно улучшить), одна строка о том, для кого я работаю, кнопка «Написать в Telegram», журнал работы.
2. **Проекты** (карточка: название, тип, метка статуса, стек, 2 строки «что сделано», ссылка, если есть). Пока нет скриншота, показывай честную заглушку с названием проекта, скриншоты не подделывай. Проекты по умолчанию:
   - 3D-витрина автомобиля на Three.js (концепт): открывающийся капот, вид из салона, управление камерой.
   - SiDa Candle: каталог магазина ручных свечей, галереи фото, выбор запаха, заказ в Telegram/MAX (реальный проект).
   - Telegram Mini App для магазина: каталог, корзина, заказы, макет админки (демо). Тематику товаров не раскрывать.
   - Telegram-бот с оплатой через Tribute для платного закрытого канала (в разработке, клиента не называть).
3. **Что делаю:** 4 услуги (сайт-визитка/лендинг, витрина с заказом в Telegram, Telegram-бот, Mini App). У каждой: что получает клиент, срок, цена «от».
4. **Как работаю:** 4 шага (бриф → макет → разработка → запуск и правки), сроки и число правок из моих ответов.
5. **Обо мне:** 3–4 предложения, фото или монограмма.
6. **Контакты:** кнопка Telegram с готовым текстом (`https://t.me/<username>?text=` + закодированное «Здравствуйте, Никита! Хочу обсудить проект»), остальные каналы из ответов.
7. Подвал: © год, имя.

## 6. Технические требования

- Статический сайт: HTML, CSS, JS (ES-модули), без фреймворков и сторонних библиотек на самом сайте, сборка не нужна. Инструменты проверки (Playwright, axe-core, Lighthouse, html-validate) только в `devDependencies`, на сайт не попадают.
- Семантика: `header/main/section/footer`, один `h1`, логичные `h2`, ссылка «Перейти к содержимому», видимый фокус, `aria-label` у иконок, `alt` у картинок, `lang="ru"`.
- Адаптив 360–1920 px, без горизонтальной прокрутки. Тач-цели ≥ 44 px.
- `prefers-reduced-motion`: все анимации выключаются или становятся статичными. Анимируются только `transform`/`opacity`, при скрытой вкладке анимации на паузе.
- Производительность: вес страницы без картинок до 300 КБ, картинки WebP/AVIF с `width/height`, `loading="lazy"` ниже первого экрана, `preconnect` для шрифтов.
- SEO и шаринг: `title`, `description`, `canonical` (если домен известен), Open Graph и Twitter-теги, `og:image` 1200×630 (сгенерируй скриптом в стиле сайта, без чужих материалов), favicon (SVG-монограмма «Н»), JSON-LD `Person`.
- Весь редактируемый текст лежит в `index.html`, не в JS. Недозаполненные места помечены `[ЗАПОЛНИТЬ: ...]`, команда `npm run placeholders` печатает их список.
- README: как менять тексты, как добавить скриншоты проектов, как выложить на GitHub Pages.

## 7. Самопроверка (обязательна)

`npm run qa` запускает локальный сервер и проверяет:
- **Playwright (Chromium)** на 390×844, 768×1024, 1440×900: скриншоты в `qa/screens/`; в консоли нет ошибок и предупреждений; нет горизонтальной прокрутки; все картинки и ресурсы грузятся; внутренние якоря существуют; у всех ссылок есть `href`.
- **axe-core:** ноль нарушений уровня serious/critical.
- **Lighthouse (mobile):** Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
- **html-validate:** без ошибок.

**Визуальный осмотр** (после этапов 3 и 5 и в конце): открой скриншоты и оцени по рубрике:
1. За 5 секунд понятно, кто я и что делаю.
2. Один акцентный цвет, остальное приглушено.
3. Читаемость: контраст, размер, длина строки.
4. Единая сетка и ритм отступов.
5. Атмосфера: низкий ключ, фактура, ничего «сладкого».
6. Кнопка связи видна на мобильном без поисков.
7. Нет выдуманных фактов.

Для каждого недостатка запиши в `QA.md` «что не так → что исправил», исправь и сделай новые скриншоты. Минимум 3 круга, либо пока замечаний не останется.
