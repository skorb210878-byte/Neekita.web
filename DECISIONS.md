## Дополнительные технические решения (не было явного вопроса, решено по умолчанию)

- **Менеджер пакетов:** npm (поставляется с Node, пользователь ничего другого не
  запросил).
- **Локальный сервер для `npm run qa`:** пакет `http-server` — лёгкий, кроссплатформенный,
  не требует написания отдельного http-сервера на Node с нуля ради обвязки тестов.
- **Генерация og:image/favicon:** пакет `sharp` (рендер SVG → PNG/WebP), т.к. нужно
  сделать `og:image` 1200×630 и растровые фавиконки в стиле сайта без внешних
  изображений — см. раздел 6 ТЗ.
- **`qa/run-qa.js` использует программные API, а не CLI-бинарники.** На Windows
  `spawnSync` с путём к `.cmd`-файлам (`html-validate.cmd`, `lighthouse.cmd`) падает
  с `EINVAL`, а с `shell: true` требует ручного экранирования путей и даёт
  предупреждение о небезопасности. Вместо этого используются Node-API пакетов:
  `new HtmlValidate().validateFile(...)` и `lighthouse(url, {port: chrome.port, ...})`
  с `chrome-launcher` (поставляется вместе с `lighthouse`, отдельно не ставился).
  Так и `html-validate`, и Lighthouse надёжно работают из одного процесса без
  зависимости от особенностей запуска `.cmd` в Windows.
- **Ожидание окончания CSS-анимаций перед скриншотами/axe (`ANIMATION_SETTLE_MS`
  в `qa/run-qa.js`):** первый прогон QA после добавления «журнала работы» в hero
  дал `axe-core` serious `color-contrast` — проверка попала на кадр, где строка
  журнала ещё fade-in (`opacity` < 1), что даёт временно заниженный контраст.
  Это не реальная проблема доступности (блок `aria-hidden`, декоративный,
  анимация короткая), а артефакт момента скана. Добавлена пауза 3с после
  `networkidle` перед скриншотами и перед `axe.analyze()` — дольше самой долгой
  анимации на странице. Проверено: без паузы — 1 serious-нарушение, с паузой — 0.
- **Баг в `scripts/find-placeholders.js`: построчный поиск пропускал
  многострочные `[ЗАПОЛНИТЬ: ...]`.** Комментарий про canonical/og:url в
  `<head>` занял 3 строки — ни одна строка по отдельности не содержала и `[`,
  и `]`, поэтому построчное регулярное выражение его не находило (13 находок
  вместо 14). Переписано на поиск по всему файлу одной строкой с вычислением
  номера строки по количеству переносов до найденного совпадения. Проверено:
  до фикса — 13, после — 14 (включая многострочный).
- **Финальный favicon и og:image — геометрия вместо текста там, где это
  возможно.** Фавиконка (`scripts/generate-favicon.js`) рисует букву «Н»
  прямоугольниками (две стойки + перекладина), а не текстом — шрифт Barlow
  Condensed веб-шрифт, в headless-рендеринге SVG через `sharp`/`librsvg`
  гарантии, что он будет установлен в системе, нет; геометрия рендерится
  одинаково везде. Для og:image (`scripts/generate-og-image.js`) текст всё же
  нужен (название и подзаголовок) — используется системный гротеск с цепочкой
  фолбэков `Arial Narrow, Arial, sans-serif`: на этой машине есть `Arial`,
  получилось жирно и разборчиво, хотя не идентично Barlow Condensed. На сам
  HTML-сайт это не влияет — там шрифт подключён через Google Fonts и
  рендерится в браузере пользователя, а не на сервере сборки.
- **og-image.jpg, не .png:** первая версия на PNG весила 478 КБ (зерно
  плохо жмётся без потерь), JPEG с `mozjpeg`, качество 85 — 21.8 КБ при тех
  же 1200×630. Для соцсетей (Open Graph/Twitter Card) JPEG полностью
  приемлем, прозрачность не нужна.
- **Временный favicon на этапе 1 → заменён на финальный на этапе 5.** Браузер на
  любой странице сам запрашивает `/favicon.ico`, без файла это падает в консоль
  как `404` и ломает проверку «в консоли нет ошибок» (раздел 7 ТЗ) на каждом
  этапе, а не только на этапе 5. На этапе 1 поставлена простая SVG-монограмма
  «Н» текстом (системный шрифт-засечка). На этапе 5 `assets/img/favicon.svg`
  пересобран скриптом `scripts/generate-favicon.js` — геометрическая монограмма
  в цветах сайта, плюс растры `favicon-32.png`/`apple-touch-icon.png` (см.
  решение про геометрию вместо текста ниже).
- **Скриншоты и JSON-отчёты QA в git не идут:** `qa/screens/`, `qa/*.log`,
  `qa/*.json` (`qa-results.json`, `lighthouse.json`) добавлены в `.gitignore` —
  это воспроизводимые артефакты прогона (`npm run qa` их пересоздаёт), а не
  исходники. В git идёт код (`qa/run-qa.js`) и тексты `QA.md`/`PLAN.md` с
  описанием находок, а не сами PNG/JSON. Критерий раздела 9 «все изменения
  закоммичены» относится к правкам сайта и документации, а не к бинарным
  выводам тестов. `.claude/` (служебный файл среды выполнения агента,
  `scheduled_tasks.lock`) тоже в `.gitignore` — не часть проекта сайта.
- **Git identity для коммитов:** в системе не было глобального `user.name`/`user.email`,
  поэтому выставлены **локально** (только для этого репозитория, `git config --local`):
  `user.name = Nikita`, `user.email = skorb210878@gmail.com` (почта из контекста
  пользователя). Глобальный git config не менялся.
- **Браузер для Playwright: системный Chrome/Edge, не отдельный Chromium.**
  `npx playwright install chromium` зависла на загрузке дольше 28 минут (сеть),
  пользователь явно велел её остановить и больше Chromium не скачивать. Задача
  остановлена (`TaskStop`). Вместо этого `qa/run-qa.js` запускает браузер через
  `chromium.launch({ channel: 'chrome' })` с фолбэком на `channel: 'msedge'`, если
  Chrome не найден. В системе подтверждено: `C:\Program Files\Google\Chrome\Application\chrome.exe`
  и `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` — Chrome
  используется первым. Lighthouse CLI находит системный Chrome самостоятельно через
  встроенный `chrome-launcher`, отдельной настройки не требует.
- **Этап 6: требование WebP/AVIF + `loading="lazy"` для изображений отложено
  на этап 7.** На странице сейчас нет ни одного `<img>` — скриншоты проектов
  ещё не присланы (решение этапа 3), карточки используют CSS-заглушку.
  Выполнять требование не на чем; придумывать изображения, чтобы формально
  закрыть пункт, нарушило бы правило «не выдумывать» (раздел 2 ТЗ). Вместо
  этого честно зафиксировано как отложенное в `PLAN.md`, будет закрыто на
  этапе 7 вместе с реальными скриншотами.
- **Два новых скрипта для этапа 6 вместо встраивания в `qa/run-qa.js`:**
  `scripts/check-responsive.js` (79 ширин 360–1920px с шагом 20px) и
  `scripts/check-page-weight.js` (вес HTML+CSS+JS). Сделаны отдельными
  командами (`npm run check:responsive`, `npm run check:weight`), а не
  добавлены в основной `npm run qa`, чтобы не раздувать обычный прогон —
  они разовые проверки этапа, а не часть регулярного QA-цикла (3 вьюпорта в
  `run-qa.js` уже покрывают регрессии на каждом этапе).
- **Этап 7: заглушка карточек проектов заменена на настоящие скриншоты.**
  На этапе 3 было решено ждать скриншоты от пользователя («скриншот
  появится позже»). К этапу 7 ждать дальше не имеет смысла — оба проекта
  уже живые и доступны по HTTP (проверено `curl`, 200 на обоих), а правило
  раздела 10 «не подделывать скриншоты» требует реальных, а не нарисованных
  превью. Снято новым скриптом `scripts/capture-project-screenshots.js`
  (Playwright, системный Chrome, `networkidle` + 1.5с на анимацию/3D-модель)
  и сжато в WebP через `sharp` (800×500, качество 80). Скриншот BMW M5 G90
  получился тёмным — это честная передача реальной сцены (тёмный фон
  3D-витрины), не брак рендера. `.project-card__media` в CSS упрощён под
  реальное изображение (`object-fit: cover`), старые классы
  `__media-mark`/`__media-note` (текст-заглушка) удалены как неиспользуемые.
  Это заодно закрывает отложенное на этапе 6 требование
  WebP + `width/height` + `loading="lazy"`.
- **Пользователь заменил скриншот BMW M5 G90 на свой (полный кадр витрины
  1920×1080, с заголовком и характеристиками), а не на автоматический
  снимок верха страницы.** Файл был подставлен как PNG под именем
  `bmw-m5-g90.webp.png` (неверное расширение — фактически PNG, не WebP).
  `object-fit: cover` у `.project-card__media img` обрезал его по бокам
  (контейнер 16:10, фото 16:9) — часть текста и цифр уходила за край
  карточки. Исправлено: `object-fit: contain` + фон `var(--surface-2)` на
  контейнере (целиком влезает, без обрезки, с admissible "полями" по краям
  вместо кропа — безопасно и для старого скриншота SiDa Candle, у которого
  пропорции и так совпадают с контейнером, видимой разницы там нет). Файл
  пересжат в настоящий WebP (`sharp`, 1280×720, quality 82): 717 КБ → 20 КБ.
  Старый `*.webp.png` удалён, `src`/`width`/`height` в `index.html` поправлены.
